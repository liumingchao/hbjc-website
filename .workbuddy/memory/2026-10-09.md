## 交付：expandable container house 外贸独立站（纯静态多页）

**背景**：用户要做扩展房（expandable container house）外贸独立站，参考 hbtygbhouse.com，要求纯静态 HTML + Tailwind + 原生 JS、多页面、10 项改进。
**产出目录**：`/Users/liumingchao/Documents/WORK/PROJECT/hbjc/`（11 个 HTML + 1 个共享自定义 CSS + 2 个 JS + 34 张脚本生成的 SVG 占位图 + 2 个生成器脚本 + README）

### 关键技术决策（下次复用）
- **Tailwind 走本地编译而不是 Play CDN**：`npm i -D tailwindcss@3.4.17` → `npx tailwindcss -i assets/css/tailwind.src.css -o assets/css/tailwind.css --minify`。产物约 20 KB，不依赖外网（用户在国内，CDN 会慢/被墙）。自定义组件全部写在手写的 `style.css`（不用 `@apply`），编译产物不动。
- **占位图脚本化生成**（`tools/generate-placeholders.mjs`）：工程蓝图风格 SVG（产品立视图带尺寸线 / 户型图 / 室内 / 工厂 / 案例 / 博客头图 / Hero），34 个文件用一个脚本 + 数据表生成，比手写省一个数量级。注意：SVG 文本必须转义 `&`，否则 XML 不合法（踩过）。
- **4 个产品详情页用生成器产出**（`tools/generate-product-pages.mjs`）：结构完全一致、只有参数不同，数据驱动生成一次，避免手写 4 遍产生不一致。
- **联系方式集中在一个配置文件**：`assets/js/site-config.js` 暴露 `window.SITE_CONFIG`，HTML 里写 `data-site="phone"` / `data-href="whatsapp"` 占位 + 兜底文字，JS 启动时覆盖。改电话只改一个文件。
- **WhatsApp 悬浮按钮由 JS 注入**，保证 11 个页面绝对一致，不用复制 11 遍。

### 踩坑（重要）
1. **`npm install` 报 EACCES（`~/.npm` 里有 root 拥有的文件）**：不要 `sudo chown`（风险大），改用独立缓存目录：
   `npm_config_cache=/Users/liumingchao/.workbuddy/tmp/npm-cache npm install`
2. **375px 手机端横向溢出**，两个不同原因，都要修：
   - 导航栏：品牌副标题 "EXPANDABLE CONTAINER HOUSE" 宽 172px + 右侧按钮组 174px 撑爆 → 副标题 `hidden sm:block`、logo 图标响应式、按钮 `px-3 sm:px-4`、容器 `px-4 sm:px-5`
   - **栅格子项的自动最小尺寸等于内容最小宽度** → 内部 `min-width:40rem` 的宽表格和 7 个横排缩略图把 12 栅格撑到 650~710px。修法：`.grid > *, .flex > * { min-width: 0 }`；同时把 `.table-scroll table` 的 min-width 从 40rem 降到 20rem，只有多列对比表才加 `.wide`（44rem）
3. **生成的 SVG 里标题块写在左上角，会被卡片角标压住** → 把标题条统一挪到图片底部（navy 色带），左上角留给角标
4. **`data-count` 计数器会覆盖元素里所有文字**，`$` 前缀要放在 span 外面
5. **macOS Chrome 无头截图有最小窗口宽度**（约 500px），`--window-size=390` 截出来会被裁切看起来像溢出 → 用 `iframe` 精确渲染窄屏再截外层页面

### 验收方法（可复用）
- 写一个探针 HTML：把目标页塞进 390px 宽的 iframe，遍历 `getBoundingClientRect().right > clientWidth` 找溢出元素，用 `--dump-dom` 把结果当文本读出来。比肉眼找溢出快得多。
- 用 `/Applications/Google Chrome.app/Contents/MacOS/Google Chrome --headless=new --screenshot` + `#锚点` 截不同区块，无需装 playwright。
- SVG 批量合法性校验：Python `xml.etree.ElementTree.parse`。

### 遗留 / 待用户处理
- 站内所有价格（$4,500 起）、工厂数据（16 年 / 52,000 m² / 5,000 台年产）、认证、案例国家、客户评价**都是按行业常识写的演示数据**，已在 README「上线前必做清单」中显著标出必须替换。
- 表单没有后端，`formEndpoint` 留空走本地演示模式。
- Google Fonts 是唯一外部请求；地图用 Google Maps embed（用户面向海外买家，合理）。

### 无头截图新踩坑（重要，可复用）
- **Chrome 无头打开本页会卡死**：页面有 Google Fonts 外链，国内网络下 `fonts.googleapis.com` 连不上导致挂起（5 分钟无输出）。解法：`--host-resolver-rules="MAP fonts.googleapis.com 127.0.0.1:9,MAP fonts.gstatic.com 127.0.0.1:9"` 把外链域名黑洞掉。
- **`.reveal` 元素在无头截图里永远是空白**：初始 `opacity:0`，靠 IntersectionObserver 加 `.is-visible`，无头环境下不触发。解法：加 `--force-prefers-reduced-motion`（style.css 的 reduce 媒体查询里 `.reveal` 直接 `opacity:1`）。**排查"页面是不是空的"之前先加这个 flag，否则会误判成 bug。**
- 后台起的 `python -m http.server` 会随 shell 退出而消失 → 用 `run_in_background` 起，别用 `(cmd &)`。

## 追加二：图片目录重构 + favicon + meta description 修正

### 用户提的三件事，两件的**前提判断是错的**，要如实说明
1. 「很多图共用一个，后期维护商品是灾难」→ **完全成立，且比想象严重**：`products.html` 8 个产品卡只有 4 张图，后 4 个产品（FP-20 平pack / DT-40 拼装 / AB-30 卫浴 / OF-20 办公）直接借用前 4 个的立视图 —— 平板打包卡上印的标题是「20FT EXPANDABLE」。4 个产品详情页的 4 张室内图也完全共用。共 160 处图片引用。
2. 「HTML 里没有 `<meta name="description">`」→ **事实错误：11 页全都有**。真正的问题是**全部超长**（首页 222 字符，其余 166–203），Google 约 155–160 字符截断，超长时它会弃用 description 改从正文抓取 —— 这才是用户「搜索结果显示的是页面前几段文字」的真实原因。诊断错、病灶对。
3. 「浏览器标签页没有图标」→ 有 `<link rel="icon" href="assets/img/logo.svg">`，但 **logo.svg 是 360×96 的横版**，塞进 16×16 标签页基本糊成一条；且 Safari 不认 SVG favicon。→ 正解是补方形 `.ico`。

### 最终图片目录结构（已落地，57 个文件 / 15 个目录）
```
assets/img/
  icons/    logo.svg  favicon.svg  apple-touch-icon.png
  home/     hero-blueprint.svg
  products/ <型号>/  cover.svg floorplan.svg interior-{living,kitchen,bedroom,bathroom}.svg factory.svg
            型号目录：20ft-expandable / 30ft-expandable / 40ft-expandable / apple-cabin
                       flat-pack / detachable / ablution / site-office（后 4 个只有 cover）
  factory/  workshop.svg line.svg yard.svg qc.svg video-poster.svg
  projects/ <国家代码>.svg（9 张）
  blog/     <slug>.svg（7 张，新增 insulation）
根目录 favicon.ico（16/32/48）
```
**核心原则：一个商品 = 一个目录，改一个商品的图不影响任何别的商品。**

### 关键做法（下次复用）
- **先 `git rev-parse` 确认有干净基线再用**。这个项目是 git 仓库且工作区干净，等于免费的回滚点，才敢做 48 文件的重构。不是 git 仓库就先备份。
- **改生成器 → 重跑 → 逐字节对比新旧产物**：`sha256` 对比 30 组，全部一致 → 证明 `elevation()` 的 `banner/fold/door/front` 参数化重构是行为保持的（尤其 `front` 默认值写成 `m.panels===1?'glazing':'windows'`，苹果舱输出的字节没变）。这一步让"重构没夹带私货"可验证，而不是靠眼看。
- **图片引用批量替换必须"按出现顺序"而不是按字典**：`products.html` 里 `product-20ft.svg` 出现两次但目标是两个不同目录（20ft 卡 vs 平板打包卡），字典映射会错。做法：正则取出全部匹配，按顺序配一个等长的目标列表，再从后往前回写。脚本里对这两个文件用显式 ORDERED 列表 + `assert len()==len()` 兜底。
- **手工改产物 vs 改数据源这条坑踩了两次**：① 我先前直接改了 4 个产品页的 `<meta description>`，一重跑 `generate-product-pages.mjs` 就被 `MODELS[].metaDesc` 覆盖回去 → 必须同步改数据源。② 同理 HTML 里的图片路径也由生成器模板产出。**结论：任何"产物 + 生成器"并存的静态站，改产物后必须回头改数据源，并再重跑一次做 diff 验证。**
- **favicon 不依赖任何第三方库**：`tools/make-favicon.py` 自己光栅化（4× 超采样抗锯齿）+ 手写 PNG（zlib+CRC32）与 ICO（PNG-in-ICO）编码。`os.path.join(dirname(__file__), '..')` —— 我一开始写成 `'..','..','..'`，结果把文件生成到了 `/Users/liumingchao/Documents/WORK/` 下，已清理。**计算相对路径后要立刻 `print(root)` 确认。**
- **SVG 文本转义**：生成器里 `t()` 会 `esc()` 一次，所以数据里写 `&` 而不是 `&amp;`；写了 `&amp;` 会输出 `&amp;amp;`（踩过，已修）。校验脚本加一条 `'&amp;amp;' in s` 检查。
